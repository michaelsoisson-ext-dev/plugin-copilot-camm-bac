## When to Use This Skill

Generate and update project documentation including API docs, setup guides, and inline code documentation.

## Ask for:

1. **What to document** (API endpoints, setup guide, configuration, component, etc.)
2. **Documentation type** (README, API docs, JSDoc, configuration guide, etc.)
3. **Target audience** (developers, ops, users, etc.)

## Documentation Types

- **README.md**: Project overview, quick start, tech stack
- **API Documentation**: Endpoints, request/response examples, auth
- **Setup Guide**: Development environment, dependencies, configuration
- **JSDoc**: Function/class documentation with examples
- **Architecture**: System design, data flow, component relationships
- **Configuration**: Environment variables, settings documentation
- **Troubleshooting**: Common issues and solutions

## Requirements

- Always read `.github/copilot-instructions.md` in the current working directory first to understand the project's architecture, conventions, and commands
- Follow project's documentation standards from `.~/.copilot/installed-plugins/orange-camm-bac/camm-bac/instructions/documentation-camm-bac.instructions`
- Include code examples where appropriate
- Format using Markdown with clear structure
- Keep documentation synchronized with code
- Use JSDoc format for code documentation
- Include practical examples and use cases
- Ensure documentation is accessible and clear
